# 구성과 원고

## 목차

- 길이별 기준값
- 쇼릴(작업 모음·자기 소개)
- 용도별 참고 구성
- 카피 규칙
- 발음 표기 규칙(tts)

## 길이별 기준값

과거 제작 13건과 평가 실행에서 나온 값이다. 나레이션 글자 수는 **발음 표기(tts) 기준, 공백 제외**다.

| 길이 | 나레이션(넣을 때) | 발화 비율 | 장면 | 구도(화면 상태) | 편집 리듬 |
| --- | --- | --- | --- | --- | --- |
| 15초 | 50~65자, 4~6줄 | 55~60% | 4~6개 | 10~14개 | 박마다 무언가 바뀐다. 메시지 하나와 이름·CTA |
| 30초 | 100~130자 | 60~70% | 6~10개 | 15~22개 | 반 마디~1마디마다 구도가 바뀐다. 헤드라인 위주 |
| 60초 | 220~255자, 12~16줄 | 60~70% | 7~12개 | 25~35개 | 쇼릴이면 구간 6~10개, 구간당 3~8초 |
| 100초 | 360~420자, 18~19줄 | 60~70% | 6막 15~25개 | 40~50개 | 막마다 템포를 바꾼다 |
| 120초 | 300~380자, 22~28줄 | 55~65% | 7~8막 15~25개 | 45~60개 | 큰 히트 4~6번, 그 앞뒤 2~4초는 나레이션을 비운다 |
| 5분 | 1,150~1,300자 | 80~90% | 약 25개 | 90~120개 | 챕터 카드 → 장면 3~6개 × 3~4챕터 → 정리 → 다음 편 예고 |

- 표의 장면·구도 수는 과거 제작에서 나온 값이다. 콘셉트가 다른 구조(컷 없는 원테이크 등)를 요구하면 따르지 않는다.
- **구도**는 화면의 주된 배치가 바뀌는 단위다. 한 장면 안에서도 단어가 크게 바뀌거나, 카드가 재배치되거나, 카메라가 다른 곳으로 가면 새 구도다. 같은 구도가 2마디(약 4초)를 넘으면 그 안에서 무엇이 바뀌는지 확인하고, 의도한 정지가 아니면 구도를 바꾼다. 장면 수만 맞추고 구도를 한 장면에 하나씩 두면 영상이 멈춰 보인다(평가에서 스킬 없이 만든 영상보다 덜 역동적으로 보인 원인이었다).
- Marcus(multilingual_v2, speed 1.0)는 문장형 줄을 초당 약 5.5자로 읽는다. "기획."처럼 짧은 줄이나 마침표·쉼표가 여러 개인 줄은 초당 3~4.7자로 느려진다. 짧은 줄이 많은 원고는 글자 수를 표의 하한보다 15~20% 줄인다.
- 발화 비율을 70% 넘게 채우면 큰 히트와 몽타주가 들어갈 자리가 없다. 2분 원고를 448자로 썼다가 발화가 82%가 되어 400자로 줄인 사례가 있다.
- 처음부터 이 분량으로 쓴다. 81.7초짜리 원고를 speed·atempo로 줄인 사례가 있었는데, 낭독이 빨라져 웅장한 느낌이 사라졌다.
- 나레이션이 없는 영상은 화면 글자를 한글 초당 6~8자 이상 읽을 시간을 준다.

## 쇼릴(작업 모음·자기 소개)

이력서용 쇼릴은 서로 다른 작업의 가장 좋은 구간을 음악에 맞춰 이어 붙이고 이름(과 연락처)으로 끝나는 형식이다. 설명하는 영상이 아니라 보여 주는 영상이다. 아래는 이 형식을 만들 때 정할 것들이다. 구간 수와 순서는 콘셉트가 정한다.

- **첫 5초**: 가장 강한 구간을 둔다. 이름 카드로 시작한다면 이름 카드 자체가 첫 작업이 되게 만든다.
- **구간의 차이**: 구간마다 다른 프로젝트처럼 보이게 한다. 매체, 팔레트, 서체, 움직임의 성격 가운데 적어도 두 가지가 앞 구간과 다르다. 정하는 방법은 `design.md`의 "아트 디렉션 정하기".
- **실제 의뢰 작업이 없을 때**(Claude 자신의 쇼릴): 가상 의뢰를 세운다. 예: 음악 방송 타이틀, 뉴스 데이터 그래픽, 스포츠 중계 패키지, 영화 타이틀 시퀀스, 앱 제품 영상, 브랜드 로고 애니메이션, 어린이 채널 아이디, 전시 포스터 모션. 가상 브랜드의 이름과 표장은 새로 짓고 실존 회사를 흉내 내지 않는다. 구간 안 카피는 한글로 쓴다.
- **코드로만 할 수 있는 것**: 수천 개 요소가 규칙에 따라 움직이는 생성 그래픽, 물리 계산, 음악 분석 데이터로 움직이는 화면, 셰이더, 한글 윤곽 변형. 사람이 손으로 키프레임을 잡기 어려운 표현을 한두 구간에 넣으면 이 영상을 만든 쪽이 무엇을 할 수 있는지가 드러난다.
- **구간 연결**: 매치 컷, 형태 변형, 색 이어받기처럼 앞 구간의 무언가를 다음 구간이 받는다. 컷마다 연결 방식을 바꾼다(`design.md`의 "전환").
- **카피**: 구간 이름(가상 의뢰명이나 작업 종류)과 이름 카드 정도로 줄인다. 설명 문장을 늘어놓지 않는다.
- **음악**: 한 곡의 섹션을 구간과 맞추고, 구간 경계를 마디에 놓는다. 클라이맥스 앞에 정지나 브레이크다운을 두면 대비가 생긴다.
- **엔드카드**: 이름(Claude 자신이면 "Claude")과 한 줄 소개. 마지막 1.5~2초는 이름을 읽을 시간을 준다. 끝 화면의 디자인은 마지막 구간의 아트 디렉션으로 정한다.

## 용도별 참고 구성

과거 제작에서 쓴 구성이다. 콘셉트가 다른 구성을 요구하면 따르지 않는다. 시간은 60초 기준이며, 다른 길이는 비율을 맞춰 줄이거나 늘린다.

### 인물 프로필 (이력서·소개)

| 구간 | 시간 | 내용 |
| --- | --- | --- |
| 콜드 오픈 | 0~8초 | 그 사람의 분야를 네 단어로 몽타주하거나 시대·문제를 한 문장으로 던진다 |
| 정체성 공개 | 8~10.5초 | 이름(또는 정체성 문장)을 큰 히트와 함께 공개 |
| 경력 챕터 | 10~48초 | 연대순 4~6챕터. 챕터마다 직함 하나 + 증거 숫자 하나 + 실제 사진 한 장 |
| 현재·수렴 | 42~52초 | 지금의 직책과 그 의미를 한 문장으로 |
| 태그라인·이름 카드 | 52~60초 | 태그라인 → 마지막 히트 → 이름·직함·경력 크레딧 |

예: "방송. 음악. 아티스트. 그리고, 콘텐츠." → "1993년, KBS 예능 PD." → … → "이훈희."

### 기업·브랜드 홍보

| 구간 | 내용 |
| --- | --- |
| 문제 제기 | 고객이 겪는 문제를 숫자나 장면으로(계약서 더미, 경고 시계) |
| 브랜드 공개 | 로고 조각 조립·라이트 스윕, 슬로건 |
| 기술·해법 | 핵심 기술을 다이어그램·파티클로 |
| 제품 시연 | UI 목업을 코드로 그려 실제 사용 흐름을 보여 준다(스캔 → 하이라이트 → 수정 제안) |
| 증거 | 수치 카운트업(출처 있는 것만), 고객사 이름(로고 대신 텍스트) |
| 비전·CTA | 한 문장 비전 → 로고 → URL |

100초 브랜드 필름은 6막(혼돈 → 등장 → 기술 → 제품 → 증명 → 비전)으로 늘리고, 1막과 6막에 2.39:1 레터박스를 둔다.

### 제품·솔루션 (15초)

질문형 도입(0~2초) → 브랜드(2~4초) → 기능 5단계를 1초씩(4~9초) → 증거 3개(9~12초) → 태그라인·CTA(12~15초).

### 행사 홍보

15초: 상징 이미지 → 행사 슬로건 → 무대 → 행사명·일시·장소 엔드카드.
60초: 도입(사람·문제) → 공백·정지(음악까지 멈춤) → 해답(행사 콘셉트) → 프로그램·연사(숫자 롤링, 이름 월) → 다음 단계 → 엔드카드(신청 버튼·일시·장소·주최).
"얼리버드 접수 중"처럼 날짜가 지나면 틀리는 문구는 납품 보고에 표시한다. 연사는 실명·소속만 쓰고 얼굴을 생성하지 않는다.

### 콘텐츠 티저 (드라마·웹툰·게임)

콜드 오픈(시각·장소가 찍힌 CCTV, 정적) → 사건 → 드롭(음악 폭발, 레터박스 열림) → 반전(음악 정지 2초) → 질문 세 개 → 타이틀. 나레이션은 짧은 단문을 쉼표로 끊는다("친구인가. 환상인가.").

### 전략·제안 (임원 대상)

콜드 오픈 질문(0~4초) → 문제의 규모(숫자·대비, 4~14초) → 전환(음악 정지 후 임팩트, 14~18초) → 해법 구조(흐름·역할, 18~36초) → 증거·시연(36~50초) → 한 문장 결론 + 요청(50~60초).
- 속도·분량 자랑("대본 3일 만에")은 상대가 만드는 사람을 가볍게 본다고 읽을 수 있으니 쓰지 않는다.
- 상대가 이미 아는 자기 회사 숫자보다 판단 결과를 보여 준다.
- 경쟁사 이름, 상대의 발언 인용, 개발자 지표(GitHub 스타)는 넣지 않는다.
- 기술 용어는 풀어 쓴다("하네스 = 역할을 나눈 AI들 + 일하는 규칙").

### 과정·시스템 설명 (하네스·연구·파이프라인)

터미널에 실제 요청을 타이핑 → Enter 섬광 → 기호를 확대하는 매치 컷 → 에이전트·단계 그래프(카메라가 훑음, 카운터) → 단계별 헤더(번호 + 역할 이름) → 실제 산출물 발췌 → 검수 통과 스탬프(효과음과 같은 프레임) → 병렬 진행 바·경과 시계 → 총계 → 첫 문장을 되받는 마지막 문장.
- 숫자는 실제 실행 기록(로그·JSON)에서 가져온다.
- 결과는 실선, 도구 호출은 점선처럼 표기 규칙을 정해 끝까지 지킨다.
- 코드로 그린 그림(의료 영상, 데이터)에는 "설명을 위해 그린 그림"이라고 적는다.

### 교육 (5분 · 시리즈)

콜드 오픈(7~9초, 숫자로 시작하는 도입) → 에피소드 타이틀(4~5초) → [챕터 카드 2.8초 → 장면 3~6개] × 3~4 → 정리("정리합니다. 하나, … 둘, … 셋, …") → 다음 편 예고 한 문장 → 엔드카드.
- 화면에는 키워드·숫자·짧은 헤드라인만 띄우고, 나레이션 전문은 아래 자막으로 보여 준다.
- 데이터형 장면(막대·도넛·게이지·비교)과 실제 장면(원본 스크린샷·생성 이미지)을 번갈아 쓴다.
- 완성 뒤 사용자가 제목·썸네일을 따로 요청한 사례가 있으므로, 제목 후보 3개와 썸네일을 함께 낸다.

### 음악 기반 (나레이션 없음)

음악 구조(도입 → 전개 → 정지 → 클라이맥스 → 종결)를 막으로 쓴다. 음원의 온셋을 분석해 컷을 박에 맞추고(`music_tools.py analyze`), 화면 문구는 짧은 시 형식으로 쓴다. 기존 녹음을 쓰면 녹음의 저작권(작곡이 퍼블릭 도메인이어도 녹음은 국가별로 다름)을 CREDITS 와 보고에 적는다.

### 개인·취미 (반려동물·가족)

이름을 이용한 콘셉트 한 줄("방이 + 탄이 = 방탄") → 120 BPM 박 격자 위에 장면을 마디 단위로 → 실제 영상·사진 + 같은 대상을 닮게 만든 생성 사진 → 하루 일과 같은 반복 구조 → 하트·로고 엔드카드. 카피는 대상의 시점으로 쓴 반말 의성어와 중계 패러디가 잘 맞았다. 지어낸 설정(특기·성격)은 보고에서 확인을 받는다.

### 메이킹 필름

지어낸 장면 대신 실제 기록을 쓴다. 파일 수정 시각으로 진행 시계를 만들고, 실패한 이미지와 수정 전후, 실제 코드와 줄 수를 STEP 01~08로 보여 준다. 마지막에 완성본 하이라이트를 원래 소리로 이어 붙인다. 화면이 실제 녹화가 아니라 다시 그린 것이면 고지한다.

## 카피 규칙

- 한 화면에 메시지 하나. 글자 양은 읽는 시간(한글 초당 6~8자)으로 정하고, 길이·줄 수·강조는 그 구간의 타이포 설계가 정한다.
- 형용사("혁신적인", "획기적인") 대신 숫자·직함·연도·고유명사를 쓴다.
- 직함과 기관명은 정식 명칭을 그대로 쓴다.
- 카피의 문체(단문 나열, 반복 문형, 질문형)는 콘셉트와 구간의 아트 디렉션에 맞춰 정한다. 한 가지 문형을 영상 전체에 반복하지 않는다.
- 화면 글자와 나레이션이 같은 말을 동시에 하면 화면 쪽을 줄인다(키워드만). 화면 타이포로 이미 보여 주는 줄은 번인 자막에서 뺀다(`"nosub": true`). SRT 파일에는 그대로 남는다(SRT 에서도 빼려면 `"nosrt": true`).

## 발음 표기 규칙(tts)

ElevenLabs 는 숫자·약어·영문을 제멋대로 읽는다. 화면 표기(`text`)는 그대로 두고 `tts`에 읽을 소리를 한글로 적는다.

| 1993년 | 천구백구십삼 년 | 연도는 읽는 방식대로 |
| 2026 | 이공이육 / 이천이십육 | 행사명 속 연도는 "이공, 이육!"처럼 쉼표로 끊으면 STT 오인식이 줄었다 |
| 67% | 육십칠 퍼센트 | |
| 5배 | 다섯 배 | 고유어 수사 |
| 제6대 | 제육대 | |
| KBS, AI, LLM, CIPO | 케이비에스, 에이아이, 엘엘엠, 씨아이피오 | |
| BHSN(회사 약어) | 비, 에이치, 에스, 엔 | 글자마다 쉼표 |
| GPT-4 | 지피티 포 | |
| Claude Opus 4.5 | 클로드 오퍼스 포 포인트 파이브 | 긴 이름부터 바꾼다 |
| 밋업 | 미텁 | 그대로 두면 "미섭"으로 읽혔다 |

- **브랜드명 뒤에 조사를 붙이지 않는다.** "앨리비와 함께"가 일곱 번 모두 "LEB"로 들렸다. 브랜드명은 문장 끝에 마침표로 둔다("올인원 계약 에이아이. 앨리비.").
- 한 음절 이름("뉴"), 동음이의어("회의"=會議로 들림), 받침이 약한 짧은 고유명사는 문장을 바꾸거나 화면 글자로 보완한다.
- **한 단어만 있는 줄을 만들지 않는다.** 마지막 줄을 "쇼릴."로 두었더니 테이크·모델을 바꿔도 "쇼딜", "쇼를", "소리"로 받아써졌다. "쇼릴입니다."로 늘리자 세 번 모두 맞았다. 이름으로 끝낼 때는 서술어를 붙이거나 앞 문장과 한 줄로 묶는다.
- 끊어 읽기는 쉼표와 말줄임표로 지시한다("그 아이를, 다시… 무대에 세운다.").
- 큐로 쓸 부분 문자열은 `tts` 안의 문자열 그대로 적는다(화면 표기로 적으면 못 찾는다).
- STT가 영문으로 받아 적는 단어("Meetup")나 숫자·단위를 읽는 줄("-14 LUFS" → "마이너스 십사 러프스")은 발음이 맞아도 유사도가 낮게 나온다. 그 줄에 `"alt": ["AI 에이전트 Meetup 2026", "믹스는 마이너스 십사 러프스"]`처럼 정답으로 인정할 표기를 더한다. `narrate.py`·`qa_check.py`가 text·tts·alt 중 가장 가까운 것과 비교한다.

## script.json 쓰는 법

형식 전체는 `scripts/narrate.py` 맨 위에 있다. 쓰는 순서는 다음과 같다.

1. 스토리보드의 장면 시각에 맞춰 줄마다 `at`(말이 시작될 시각)을 적는다. 첫 줄은 0.4~0.8초, 이름 공개 줄은 히트 시각에 맞춘다.
2. 장면 전환·키네틱 타이포와 맞출 단어를 `cues`로 이름 붙인다. 예: `"cues": {"name": "이훈희"}`
3. 고유명사·숫자 줄에만 `"takes": 3`을 준다.
4. 효과음(`sfx`)은 큐 이름으로 건다. 타격음은 `"align": "peak"`, 라이저는 `"align": "end"`.
5. 구간·장면 경계는 `scenes`에 적는다: `[{"id": "s01", "start": "bar1"}, {"id": "s02", "start": "music.hit2", "end": 14.0}]`. `start`·`end`는 초, 큐 이름, "큐±초"를 받는다. `timeline.py`가 `scene.s01`, `scene.s01.end` 큐를 만들고, `end`가 없으면 다음 장면의 시작(마지막은 영상 끝)을 쓴다. 나레이션이 없는 쇼릴은 이 큐로 화면 시각을 잡는다.
6. `narrate.py`(나레이션이 있을 때) → `timeline.py`를 실행하고, 겹침·초과가 나오면 `at`이나 문장을 고친다.

```json
{
  "duration": 60,
  "voice": "ibCGc01503OQd2R6i1n1", "model": "eleven_multilingual_v2",
  "settings": {"stability": 0.45, "similarity_boost": 0.8, "style": 0.4, "speed": 1.0},
  "lines": [
    {"id": "n01", "text": "방송. 음악. 아티스트. 그리고, 콘텐츠.", "at": 0.6, "cues": {"w4": "콘텐츠"}},
```

## 원고 2차 검토(codex)

codex CLI가 있으면 나레이션 원고와 화면 카피(가상 의뢰 이름, 구간 카피, 엔드카드 문구)를 다른 모델에게 한 번 읽힌다. 나레이션 원고에서는 번역투나 소리로 들었을 때 헷갈리는 말을 잡는 데 효과가 있었다. 나레이션이 없는 쇼릴은 화면 카피가 한글의 전부이므로 반드시 읽힌다.

```bash
codex exec --sandbox read-only --skip-git-repo-check --ephemeral -o <프로젝트>/research/narration_review.md - < <프로젝트>/research/narration_review_prompt.md
```

프롬프트에 넣을 기준(stdin으로 넘긴다. 인자로 넘기면 codex가 입력을 기다리며 멈춘다):

1. 번역투(그녀/그들/~의 ~ 남용)·어색한 리듬을 찾아 고칠 것
2. 소리 내어 읽었을 때 쉼과 여운이 사는지 점검할 것
3. 각 줄은 정해진 시간 안에 들어가야 하므로 글자 수를 늘리지 말 것
4. 사실(숫자·직함·연도)은 바꾸지 말 것
5. 파일을 읽거나 명령을 실행하지 말고 `| ID | 원문 | 제안 | 이유 |` 표로만 답할 것

받은 제안은 수용·부분 수용·기각을 정해 반영한다.
