# 요청 읽기와 콘셉트

## 목차

- 묻기 전에
- 물을 것과 묻지 않을 것
- 콘셉트 만들기
- concept.md 양식
- 시간·크레딧 추정
- 조사 요청 프롬프트
- 사진 수집 요청 프롬프트

## 묻기 전에

1. 사용자 요청에서 이미 정해진 항목을 표시한다. 예를 들어 "웅장한 1분 나레이션 영상"이면 분위기·길이·나레이션은 정해진 것이다.
2. `preflight.py` 결과로 쓸 수 없는 기능을 확인한다. 키가 없으면 나레이션 없이, codex가 없으면 이미지 생성 없이 만들 수 있는 콘셉트를 세운다.
3. 요청에 날짜와 요일이 함께 있으면 달력으로 대조한다. 맞지 않으면 요일을 빼고 보고에 적는다.

## 물을 것과 묻지 않을 것

사용자에게는 사용자만 아는 사실을 묻는다. 창작 결정은 Claude가 내린다. 요청에 "만들어 보세요", "전력을 다해요"처럼 맡기는 말이 있으면 창작 결정을 맡긴 것으로 본다.

| 구분 | 항목 | 처리 |
| --- | --- | --- |
| 묻는다 | 대상이 누구·무엇인지(요청에 없을 때) | 선택지 없이 한 줄로 묻는다. 대상은 선택지로 고를 수 없다 |
| 묻는다 | 실존 대상의 꼭 넣을 정보 가운데 조사로 확인할 수 없는 것(이름 표기, 일시, 장소, 신청 URL, CTA 문구) | 조사로 확인할 수 있으면 묻지 않는다 |
| 묻는다 | 사용자 자료의 위치(사진 폴더, 로고, 음원) | 실존 인물·회사 영상이고 자료 언급이 없을 때만 |
| 정한다 | 무드, 팔레트, 서체, 구성 | 콘셉트 단계에서 정한다 |
| 정한다 | 길이 | 요청에 없으면 60초 |
| 정한다 | 화면비 | 용도로 판단한다. 릴스·쇼츠면 9:16, 그 밖에는 16:9 |
| 정한다 | 나레이션 여부와 보이스 | 내용을 말로 전해야 할 때만 넣는다 |
| 정한다 | 이미지 생성 여부 | 콘셉트에 필요할 때만 |

Claude 자신이 대상인 요청("당신이 얼마나 놀라운 모션 그래픽 디자이너인지 보여주는…")은 아무것도 묻지 않고 바로 시작한다. 사용자가 "묻지 말고 바로"라고 하면 물을 항목도 조사와 합리적인 값으로 채우고 보고에 적는다.

물어야 할 사실이 있으면 한 메시지에 모아 한 번만 묻는다. 사용자만 아는 사실이므로 선택지나 추천안을 만들지 않고 열린 질문으로 쓴다.

## 콘셉트 만들기

콘셉트는 이 영상을 다른 영상과 구분하는 한 가지 생각과, 그 생각을 구간별 화면으로 옮긴 계획이다. 콘셉트가 약하면 뒤 단계에서 다듬어도 템플릿 영상과 구분되지 않는다.

### 1) 재료 모으기

- 주제에 대해 아는 것과 조사한 사실
- 쓸 수 있는 매체: DOM·캔버스·WebGL·3D는 항상 쓸 수 있다. 생성 이미지·나레이션·생성 음악은 `preflight.py` 결과에 따른다
- 길이와 음악 템포: 60초에 120 BPM이면 30마디다. 구간 경계는 마디에 놓는다

### 2) 후보 쓰기

서로 다른 방향의 후보를 3개 이상 쓴다. 한 후보의 변형 세 개는 후보 세 개가 아니다. 구조가 다른 예는 다음과 같다. 예시를 그대로 고르지 말고 주제에서 출발한다.

- 가상 의뢰 작업 모음: 업종이 다른 가상 의뢰 6~10편의 하이라이트를 이어 붙인다
- 한 대상의 변주: 한 글자나 한 도형이 구간마다 다른 매체·재질로 바뀐다
- 이어지는 카메라: 컷 없이 한 공간을 이동하며 구간이 차례로 나타난다
- 과정 공개: 만드는 과정(스케치 → 와이어 → 완성)을 영상의 구조로 쓴다

쇼릴 요청이면 어떤 구조를 고르든 구간마다 다른 작업으로 읽혀야 한다(`story.md`의 "쇼릴"). 원테이크나 변주 구조를 고를 때는 구간마다 매체·팔레트·움직임을 어떻게 바꿀지 후보에 적는다.

후보마다 다음을 적는다.

| 항목 | 내용 |
| --- | --- |
| 한 문장 아이디어 | 이 영상을 한 문장으로 |
| 첫 5초 | 0~5초에 무엇이 보이고 어떻게 움직이는가 |
| 구간 구성 | 구간 이름과 대략의 시간 |
| 한글을 쓰는 방식 | 자모, 획, 네모꼴, 가변 굵기 등을 어디에 쓰는가 |
| 새로 풀어야 할 기술 과제 | 이 영상을 위해 처음 만들어야 하는 표현(셰이더, 시뮬레이션, 글자 윤곽 변형 등) |

codex CLI가 있으면 같은 요청과 조건으로 후보를 따로 받아 함께 비교할 수 있다. 다른 모델의 후보가 섞이면 비교할 방향이 늘어난다. 명령 형식은 `story.md`의 "원고 2차 검토"와 같다(프롬프트는 stdin으로 넘긴다).

### 3) 고르기

후보마다 아래 기준을 1~5점으로 매겨 표로 남긴다. 점수가 가장 높은 후보를 고르거나, 두 후보의 강점을 합친다.

| 기준 | 질문 |
| --- | --- |
| 첫 5초 | 첫 5초만 보고도 기억에 남는가 |
| 예상 밖 | 앞 구간을 본 사람이 다음 구간의 매체·구도를 예상하지 못하는가 |
| 범위 | 매체·팔레트·움직임이 구간마다 달라 표현 범위가 넓게 보이는가 |
| 주제 고유성 | 이 주제가 아니면 성립하지 않는가 |
| 구분 | `design.md`의 "뻔한 화면"과 다른가. 다른 AI 영상과 나란히 놓아도 구분되는가 |
| 한글 | 한글의 형태가 움직임의 재료로 쓰이는가 |
| 제작 가능성 | 엔진과 남은 시간으로 이 수준까지 만들 수 있는가 |

제작 가능성이 낮다는 이유만으로 가장 강한 후보를 버리지 않는다. 기술 과제를 먼저 짧게 시험해 보고(장면 하나, 스틸 몇 장) 판단한다.

## concept.md 양식

```markdown
# 콘셉트 — <제목>

- 요청: <원문 그대로>
- 한 문장 아이디어: …
- 고른 이유: <평가 표 요약>
- 길이·규격: 60초 · 16:9 1920×1080 · 30fps · 음악 120 BPM(1마디 2초)
- 나레이션: 없음 / <보이스와 이유>
- Claude가 정한 것: 무드·길이·화면비·나레이션 여부 등과 이유

## 구간
| # | 시간(초) | 구간(가상 의뢰·주제) | 매체 | 팔레트 | 서체 | 움직임의 성격 | 질감 | 새로 풀 기술 과제 | 다음 구간으로 잇는 방법 |
| 1 | 0–6 | … | WebGL 셰이더 | #f2efe8 / #111 / #ff3b1f | Pretendard 가변 | 무겁게 떨어지고 짧게 튐 | 평면, 잉크 번짐 | 자모 윤곽이 액체처럼 합쳐짐 | 마지막 점이 다음 구간의 원이 됨 |

## 후보 비교
| 후보 | 한 문장 | 첫 5초 | 예상 밖 | 범위 | 주제 고유성 | 구분 | 한글 | 제작 가능성 | 합계 |

## 버린 후보와 이유

## 의도해서 쓰는 '뻔한 화면' 요소
- (예: 엔드카드에만 레터박스. 이유: …)
```

## 시간·크레딧 추정

아래 작업 시간은 이전 방식(스타일 프레임 1회, 초안 검수 2~3회)으로 잰 최소값이다. 구간을 다시 만드는 횟수만큼 늘어난다. 이 시간에 맞추려고 비평 반복이나 구간 재작업을 줄이지 않는다.

| 길이 | 작업 시간 | 나레이션 글자(넣을 때) | 장면 수 | 구도 수 | 최종 렌더(모션 블러 4) |
| --- | --- | --- | --- | --- | --- |
| 15초 | 30~50분 | 50~65자 | 4~6개 | 10~14개 | 약 1분 |
| 30초 | 30~60분 | 100~130자 | 6~10개 | 15~22개 | 약 2분 |
| 60초 | 50~90분 | 220~255자 | 7~12개 | 25~35개 | 3~5분 |
| 100초 | 70~120분 | 360~420자 | 15~25개 | 40~50개 | 6~9분 |
| 120초 | 60~120분 | 300~380자 | 15~25개 | 45~60개 | 10~13분(워커 2) |
| 5분 | 2~3시간 | 1,150~1,300자 | 약 25개 | 90~120개 | 15~25분 |

WebGL·3D 장면과 입자가 많은 장면은 렌더 시간이 더 든다. 초안 렌더 시간으로 최종 렌더 시간을 다시 추정한다.

ElevenLabs 크레딧(대략):

- TTS: 글자 수 × 1(재생성·takes 포함 약 1.5~2배)
- STT: 분당 소량
- 효과음: 길이를 지정하면 초당 40 크레딧(효과음 10종 × 2초 ≈ 800)
- 음악: 길이에 비례

User Read 권한이 없는 키는 잔여 크레딧을 조회할 수 없으므로 대시보드에서 확인하라고 안내한다.

이미지 생성: codex-image 장당 약 1분, 5장 병렬. ChatGPT 플랜 사용량이 장수만큼 차감된다.

## 조사 요청 프롬프트

인물·기업·행사·제품이 주제면 서브에이전트(`general-purpose`)를 백그라운드로 띄운다. 그동안 메인은 프로젝트 준비, 콘셉트 후보 작성, 기술 과제 시험을 진행한다.

```
<대상>에 대해 조사해 <프로젝트>/research/research.md 에 써라. 기억에 의존하지 말고 WebSearch·WebFetch 로 확인한 사실만 쓴다.
(WebFetch 가 막힌 사이트는 curl -sL -A "Mozilla/5.0" 로 받아 본문을 뽑는다.)
작업 파일은 모두 <프로젝트> 폴더 안에 둔다. /tmp 를 쓰지 않는다.
1. 연표: 연도 · 직함/사건 · 출처 URL · 확실도(확인 / 단일 출처 / 미확인)
2. 영상에 쓸 만한 사실 TOP 10: 숫자·직함·수상·성과 위주. 숫자는 기준 시점을 함께
3. 본인·공식 인용문(원문 그대로, 출처)
4. 서로 다른 정보(출처끼리 다른 수치·연도)와 동명이인 주의
5. 영상 자막용 짧은 카피 후보 15개(각 20자 이내, 사실에 근거한 것만)
6. 브랜드 색(공식 사이트 CSS 의 hex 빈도), 공식 로고 파일 URL
7. "대본에 넣지 말 것": 확인 안 된 학력·생년·수치
마지막에 파일 경로와 TOP 10 만 짧게 보고하라.
```

## 사진 수집 요청 프롬프트

실제 인물 사진이 필요하고 사용자가 사진을 주지 않았을 때 쓴다. 인물 얼굴을 AI로 만들지 않기 위한 단계다.

```
<인물>의 실제 사진을 모아 <프로젝트>/assets/photos/ 에 저장하고 <프로젝트>/research/photos.md 에 표로 정리하라.
작업 파일은 모두 <프로젝트> 폴더 안에 둔다. /tmp 를 쓰지 않는다.
- 우선순위: 공식 프로필·회사 보도자료 > 언론 기사 사진(og:image) > 본인 공개 SNS
- 네이버 뉴스 검색 결과 HTML 을 curl 로 받아 기사 URL 을 뽑고, 기사 HTML 의 og:image 를 받는다(브라우저 UA·Referer 지정)
- 받은 사진은 Read 로 직접 열어 본인인지(캡션에 이름과 직함이 함께 있는지), 워터마크, 해상도를 확인한다. 동명이인은 버린다
- 표: 파일명 · 원본 URL · 기사 URL · 해상도 · 내용(정면/무대/행사) · 품질
- 8~15장, 긴 변 800px 이상 우선
```
