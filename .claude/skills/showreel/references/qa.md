# 검수와 납품

## 목차

- 검수 단계
- 비평
- 점검표
- 시트를 볼 때 확인할 것
- 자동 검수(qa_check.py) 읽는 법
- 납품: 파일 이름, 보고 형식, 제작노트

## 검수 단계

| 단계 | 언제 | 무엇을 | 도구 |
| --- | --- | --- | --- |
| 1. 소재 | 이미지·누끼를 만든 직후 | 손·얼굴 이상, 글자·로고 섞임, 레터박스, 팔레트 | `prep_images.py --sheet` |
| 2. 스타일 프레임 | 구간마다 대표 프레임 1~2장을 만든 직후 | 포스터로 쓸 수준인가, 구간끼리 다른 작업으로 보이는가, "뻔한 화면" 요소가 이유 없이 들어갔는가 | `render.mjs --stills` + `contact_sheet.py --dir` |
| 3. 장면별 스틸 | 장면 하나를 쓸 때마다 | 시작+0.5 · 큐+0.4 · 끝-0.6초 | 같음 |
| 4. 초안 비평 | 모든 장면이 생긴 뒤, 고칠 때마다 | 아래 "비평"의 질문 여덟 개, 1초 간격 전체 흐름, 핵심 순간의 프레임 띠, 장면 경계 ±3프레임, 멈춘 구간·큰 움직임 | `render.mjs --scale 0.5` + `contact_sheet.py --every 1` / `--around` + `motion_check.py` |
| 5. 오디오 | 믹스 직후 | 줄별 나레이션 대 배경 dB, LUFS | `mix.py` 표 |
| 6. 완성본 | 마감 직후 | 규격·음량·휘도·정지·완성 믹스 STT·최종 시트 | `qa_check.py --stt` |

2~4단계는 비평에서 모든 구간이 "유지"가 되고 아래 점검표를 통과할 때까지 반복한다. 시트는 반드시 Read로 열어 본다. 수정한 장면은 같은 시각의 스틸을 다시 뽑아 전후를 비교한다. 파라미터를 바꿀 때 같은 프레임으로 비교하지 않으면 "너무 어두움 ↔ 하얗게 탐"을 오가게 된다.

간격 기준: 15~20초 영상은 0.5초, 60초는 1초, 100초는 2초, 5분은 3초. 잔상·빈 화면이 의심되는 구간은 0.1초 간격이나 `--around`로 프레임 단위로 본다. 간격 시트의 칸이 전환 중간에 걸려 흐리게 보이면 결함이 아니라 전환 프레임일 수 있으니 `--times`로 앞뒤 시각을 다시 뽑아 확인한다.

## 비평

기술 점검표는 결함을 찾는다. 비평은 이 영상이 "얼마나 놀라운 모션 그래픽 디자이너인지" 보여 주는지 판단한다. 초안을 뽑을 때마다 한다.

### 볼 자료

1. 1초 간격 전체 시트(`contact_sheet.py --video draft.mp4 --every 1`): 구간끼리의 차이와 전체 흐름
2. 구간마다 핵심 순간 하나의 프레임 띠: 0.033~0.1초 간격 12~20장(`render.mjs --every 0.033 --from <초> --to <초> --outdir qa/strip_sNN` 뒤 `contact_sheet.py --dir`). 정지 프레임으로는 보이지 않는 간격·예비 동작·안착·겹침을 여기서 본다
3. 구간 경계 ±3프레임(`--around`)

### 질문

| # | 질문 | 아니면 |
| --- | --- | --- |
| 1 | 이 구간의 프레임 하나를 템플릿 영상이나 다른 AI 영상 옆에 두면 구분되는가 | `design.md`의 "뻔한 화면" 요소를 찾아 빼거나 방향을 바꾼다 |
| 2 | 구간마다 다른 작업으로 보이는가(매체·팔레트·서체·움직임) | 비슷한 구간 둘 가운데 약한 쪽의 아트 디렉션을 다시 정한다 |
| 3 | 구간마다 "어떻게 만들었지" 싶은 순간이 있는가 | 그 구간의 기술 과제를 다시 세운다 |
| 4 | 한글의 형태가 움직임에 쓰였는가 | 자모·획·네모꼴·굵기를 쓰는 장면을 넣는다 |
| 5 | 프레임 띠에서 움직임에 무게와 재질이 보이는가(예비 동작, 넘침, 겹침, 후속 동작) | 이징을 요소별로 다시 설계한다 |
| 6 | 화면과 음악이 같은 리듬인가. 모든 박에 같은 크기의 사건을 두지 않았는가 | 사건의 크기를 박·마디·섹션으로 나눈다 |
| 7 | 1초 간격 시트를 처음부터 넘길 때 다음 구간이 예상되는 지점이 있는가 | 그 지점에서 다음 구간의 매체나 진입 방식을 바꾼다 |
| 8 | 이 영상에서 가장 약한 구간은 어디인가 | (매번 답한다) |

### 판정과 기록

- 구간마다 유지 / 고침 / 다시 만듦을 정하고 이유를 한 줄로 `qa/critique_NN.md`에 쓴다(NN은 초안 번호).
- 8번에서 고른 구간은 "유지"가 아니면 수치를 조정하기보다 방향을 바꿔 다시 만든다. 다시 만든 구간은 이전 판과 같은 시각의 스틸을 나란히 놓고 비교한다.
- 최종 렌더 전에 한 번은 만든 맥락이 없는 서브에이전트에게 시트와 프레임 띠, 위 질문만 주고 판정을 받는다. 만든 쪽이 놓친 문제를 찾기 위해서다. 그 판정은 서브에이전트가 응답으로 돌려주고, 메인이 같은 파일에 옮겨 적는다.
- 모든 구간이 "유지"이고 점검표를 통과하면 최종 렌더로 넘어간다.

## 점검표

화면:

- [ ] 첫 5초가 `concept.md`의 "첫 5초" 설계대로 보인다. 의도하지 않은 빈 프레임으로 시작하지 않는다
- [ ] 모든 글자를 읽을 시간이 있다(한글 초당 6~8자)
- [ ] 화면 한글 카피(구간 이름, 가상 의뢰명, 엔드카드 문구)에 번역투·어색한 조어가 없다
- [ ] 글자가 화면 밖으로 잘리거나 다른 요소·자막과 겹치지 않는다(의도한 크롭 제외)
- [ ] 한글이 기본 고딕으로 대체되지 않았다(렌더 로그의 폰트 목록, 확대 크롭)
- [ ] 숫자·고유명사·직함이 `research.md`와 정확히 같다
- [ ] 1초 넘게 멈춘 화면이 없다(엔드카드·의도한 정지 제외). `motion_check.py` 기준(멈춘 화면 비율·큰 움직임 p90)을 넘는다
- [ ] 퇴장이 페이드만으로 끝나지 않는다
- [ ] 장면 경계에 빈 프레임·잔상·앞 장면 누수가 없다
- [ ] 섬광이 화면을 회색·흰색으로 덮지 않는다(opacity ≤ 0.15, 1초에 3회 이하)
- [ ] 구간 안에서는 `concept.md`의 아트 디렉션을 지킨다. 같은 전환을 세 번 연속 쓰지 않았다
- [ ] 엔드카드에 이름·CTA 가 충분히 크고(48px 이상) 읽을 시간이 있다
- [ ] 다른 회사 로고·실존 인물 얼굴을 그리거나 생성하지 않았다. 가상 의뢰의 브랜드가 실존 회사를 흉내 내지 않는다

소리:

- [ ] (나레이션이 있으면) 줄마다 나레이션이 배경보다 9dB 이상 크다(`mix.py` 표)
- [ ] 나레이션에 리버브를 넣었다면 `mix.py`의 "말 끝 잔향"가 ✓(-32dB 이하)다
- [ ] 완성 믹스 STT 에서 모든 줄이 맞게 들린다. 특히 이름·숫자·연도
- [ ] 화면 히트와 효과음이 같은 프레임이다. 타격음이 핵심 단어를 덮지 않는다
- [ ] -14 LUFS ±1, true peak ≤ -1 dBFS

규격:

- [ ] H.264 · yuv420p · tv 범위 · BT.709, 프레임 수 = 길이 × fps
- [ ] 오디오 AAC 48kHz, faststart
- [ ] 공유용 파일이 메신저로 보낼 만한 크기다(60초에 25MB 안팎)

## 시트를 볼 때 확인할 것

과거 제작에서 실제로 나온 결함이다.

- 카메라가 움직이는 0.3초 동안 화면이 비는 구간
- 화면 가장자리에 앞 요소가 남은 잔상
- 보간 중에 두 요소가 스치며 겹침
- 장면 누수: 끝난 장면의 이미지가 다음 장면 뒤에 남음
- 카운터가 너무 빨라 숫자를 읽을 수 없음, 진행률이 음수라 "-2줄"처럼 나옴
- 선이 글자를 가로지름: 글자에 배경색 halo(text-shadow)를 주거나 선을 비킨다
- 구도가 위로 쏠려 화면 아래 40%가 빔
- 자막이 그래픽을 가림(완성 MP4에서만 드러난 사례가 있다)
- 코드로 그린 도식이 엉뚱한 모양으로 읽힘(예: 심장 단면의 유두근이 눈처럼 보임)
- 엔드카드가 너무 작음, CTA 가 가장 작은 글자

## 자동 검수(qa_check.py) 읽는 법

```bash
python3 $S/qa_check.py out/<이름>.mp4 --timeline timeline.json --script script.json --stt
```

- **섬광 과다**: 1초에 밝기 급변이 3회를 넘었다. 플래시 세기와 횟수를 줄인다(광과민성 발작 위험).
- **움직임**: 멈춘 화면 비율·1초 넘는 멈춤·큰 움직임 p90 을 본다(필름 그레인이 있어도 멈춤을 잡는다). 멈춘 구간에는 미세한 드리프트보다 새 사건(등장·재배치·카메라 이동)이나 장면 뒤 움직이는 면이 효과가 크다. p90 이 낮으면 화면 전체가 크게 바뀌는 순간(구도 전환, 큰 이동, 매체 전환)이 부족하다. 무엇으로 채울지는 그 구간의 아트 디렉션으로 정한다.
- **어두운 구간**: 어둡고 밝은 요소도 거의 없는 빈 화면만 잡는다. 어두운 무드의 정상 장면은 걸리지 않는다.
- **흰 프레임**: 어두운 화면 사이에 0.3초 안쪽으로 튀는 밝은 프레임(과한 플래시)만 센다. 밝은 바탕으로 디자인한 구간은 "밝은 구간"으로 참고만 적는다.
- **STT ✗**: 숫자가 다르거나 유사도 0.85 미만이다. 같은 결과가 두 번 나오면 고친다. 고치는 순서는 `audio.md`의 "나레이션 생성과 발음 검증"에 있다.
- 최종 시트(`qa/final_sheet*.png`)를 Read로 본다. 자동 검사는 글자 겹침·폰트 대체·오탈자를 잡지 못한다.

## 납품

### 파일 이름

`<제목>_<길이>s.mp4`(마스터), `<제목>_<길이>s_공유용.mp4`, `<제목>_<길이>s_포스터.jpg`, `<제목>_<길이>s.srt`. 제목은 한글이어도 된다(예: `이훈희_CIPO_쇼릴_60s.mp4`). 여러 길이를 만들면 길이만 바꾼다.

```markdown
| 자막 | /…/out/<제목>_60s.srt | |
| 제작노트 | /…/제작노트.md | |

미리보기(브라우저): `node <S>/render.mjs --dir <프로젝트>/reel --serve`

### 콘셉트
- 고른 콘셉트 한 문장과 고른 이유, 버린 후보

### 구성
| 시간 | 구간 | 매체·아트 디렉션 | 나레이션 | 화면 |

### 판단한 것
- Claude가 정한 것(무드·길이·화면비·나레이션 여부 등)과 이유
- 비평에서 다시 만든 구간과 이유(`qa/critique_*.md`)
- 요청과 다르게 반영한 것(조사 결과와 다른 경력 순서 등)과 이유
- 쓰지 못한 기능과 대체 경로(예: Music API 불가 → 합성 음악)

### 공개 전 확인할 것
- 보도 사진 사용 허락, 서명·직인이 보이는 사진
- 단일 출처 사실, 시점이 지나면 틀리는 문구(얼리버드 등)
- AI 생성 이미지 속 인물은 가상 인물
- 소리: Claude는 소리를 들을 수 없어 수치(음량·STT·나레이션 대 배경)로만 확인했다. 스피커나 이어폰으로 한 번 들어 봐 달라고 요청한다

### 고칠 때
- 문구·나레이션: script.json 수정 → narrate.py → timeline.py → (장면) → render → mix → finish
- 오디오만: mix.py → finish.py (영상 재렌더 불필요)
```

### 제작노트.md

프로젝트 폴더 최상위에 둔다. 다음 작업자(또는 다음 세션)가 그대로 다시 만들 수 있게 쓴다.

- 콘셉트 요약(고른 것, 버린 후보), 구성표(시간·구간·장면·나레이션·근거 출처), 비평 기록 위치
- 쓴 도구·모델·보이스·설정(voice_id, model, settings, 음악 플랜 또는 합성 스펙)
- 사진 출처 표, AI 생성 이미지 목록과 프롬프트 위치(`assets/gen/.codex-imagegen-logs/`)
- 요청과 다르게 반영한 사실, 공개 전 확인 사항
- 재생성 명령(위 "고칠 때"와 같은 순서, 실제 경로로)
- 지우면 안 되는 파일: `audio/vo/`(다시 만들려면 크레딧이 든다), `audio/music/`, `assets/gen/`. 정리를 요청받아도 이 파일들은 남기고, 지운 것과 남긴 것을 나눠 보고한다
